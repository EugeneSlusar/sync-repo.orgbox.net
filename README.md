# sync-repo

Универсальный Bash-скрипт для установки, настройки и синхронизации проекта с удалённым Git-репозиторием.

Скрипт помогает:

- инициализировать Git в проекте;
- подключить GitHub/GitLab-репозиторий;
- настроить ветку и авторизацию через SSH Deploy Key или токен;
- получить актуальный код и синхронизировать рабочую копию сервера.

Настройки и секреты сохраняются локально и не должны добавляться в Git.

## Запуск

Запустите скрипт из корня нужного проекта:

```bash
bash /path/to/.deploy/sync_repo_from_git.sh
```

По умолчанию проектом считается текущий каталог, а служебные настройки сохраняются в `.deploy/sync_repo_from_git.conf`. Каталог проекта можно указать явно через `GIT_REPO_DIR`.

Начиная с версии `1.3.8`, синхронизация не выполняет общую очистку файлов. Неотслеживаемые файлы, включая ядро Битрикса, загрузки и локальные настройки, сохраняются. Переменная `GIT_CLEAN=1` больше не включает удаление.

Перед обновлением скрипт проверяет локальные изменения отслеживаемых файлов и неопубликованные коммиты. При их наличии обновление останавливается. Конфликты путей с существующими неотслеживаемыми или игнорируемыми файлами также останавливают обновление: принудительная перезапись отключена.

Изменения файлов, которые отслеживаются Git, включая их удаление в целевой ветке, применяются при обычном обновлении. Настройки и секреты должны оставаться вне истории Git.

Для просмотра локальных правок:

```bash
git diff
git diff --cached
```

В дальнейшем этот инструмент станет основой для настройки автодеплоя: резервного копирования, миграций, перезапуска сервисов, проверки работоспособности и отката при ошибке.

## Интерактивное управление

При запуске экран очищается, затем скрипт последовательно запрашивает параметры обычным вводом и показывает итоговую таблицу перед синхронизацией.

При запуске в обычном проекте скрипт автоматически проверяет свежую версию в центральном репозитории и обновляет локальный файл `.deploy/sync_repo_from_git.sh`. Перед заменой проверяется синтаксис Bash; после замены скрипт сразу перезапускается с исходными аргументами, включая `--auto`. В самом центральном репозитории автообновление отключается автоматически. Для отключения проверки задайте `SYNC_REPO_AUTO_UPDATE=0`.

При переходе с `1.3.7` рекомендуется сначала скачать новый скрипт отдельно и проверить `--version`: старая версия после самообновления продолжает текущий запуск со старой логикой.

Текущую версию можно узнать без запуска синхронизации:

```bash
bash .deploy/sync_repo_from_git.sh --version
```

Если репозиторий уже подключён, пункт `3) Настроить автодеплой через GitHub Actions` запускает полуавтоматический мастер на сервере. Мастер создаёт SSH-ключ и workflow, а затем показывает значения secrets, которые нужно один раз добавить в настройках GitHub.

Повторный запуск мастера не создаёт новый ключ, если Actions-ключ уже найден на сервере, поэтому существующие secrets можно использовать повторно.

Мастер также выводит полный текст workflow и инструкцию для добавления файла через GitHub Web: `Add file` → `Create new file` → `.github/workflows/deploy.yml` → `Commit changes` в `main`.

При настройке мастер красным предупреждает: SSH-ключи и `sync_repo_from_git.conf` нельзя добавлять в Git-репозиторий. Приватный Actions-ключ используется только как GitHub Secret.

Если проект ещё не подключён к Git, мастер предлагает подключить существующий репозиторий или создать новый GitHub-репозиторий из текущей папки. Для создания нужен установленный и авторизованный [GitHub CLI](https://cli.github.com/): `gh auth login`.

## Проверка

```bash
bash -n .deploy/sync_repo_from_git.sh
python3 tests/test_sync_repo.py
```

Тесты используют временные локальные Git-репозитории и подменяют сетевой запрос самообновления. Они проверяют обновление кода, первую установку, сохранность локальных данных, остановку при правках и конфликтах, а также самообновление.
